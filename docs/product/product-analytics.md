# Mesure produit interne — #42, #484–486

La collecte est désactivée par défaut. Backend product-analytics.enabled, BFF PRODUCT_ANALYTICS_ENABLED et ADMIN_API_TOKEN côté serveur sont nécessaires, ainsi que le réglage durable ARG_PRODUCT_SETTING administré dans /account/admin/analytics. Aucune activation ou intervention en production dans cette PR.

Accord explicite facultatif : accepter, refuser et retirer depuis « Gérer mes cookies ». Le consentement est renouvelé pour le parcours compte avec argos_product_consent_v2. Cookie HttpOnly SameSite Lax de session, sans identifiant de visiteur ; le retour OAuth peut ainsi recevoir le choix. Pas de localStorage. Les mutations gardent origine et CSRF, les accès privés leurs vérifications serveur.

Les tables de mesure excluent URL soumise, token ou hash de token, email, IP, nom et contenu privé. Des références internes de run, de compte et de session sont nécessaires à l’unicité et aux cohortes : elles sont pseudonymes et ne quittent pas le stockage interne. Les API analytics exposent uniquement des agrégats. Les lectures fonctionnelles d’un rapport restent naturellement protégées par son token ; celui-ci ne devient pas un événement.

Compteurs journaliers UTC : pages publiques fermées, exemple affiché, CTA audit, refus par catégorie, formulaire d’inscription affiché. Attributions par run créé après consentement, audience figée à la création, états dérivés du métier et premier affichage du rapport dédupliqué par run. Le parcours compte ajoute inscriptions réellement créées, connexions réussies, rattachements et activité quotidienne. Les reprises idempotentes ne produisent pas de succès supplémentaires ni de reprise historique.

Administration /account/admin/analytics : périodes 7/30/90 jours. Audits par source/langue/emplacement/audience ; file, traitement et total médiane p90 p95 par rang proche. Dates manquantes ou inversées exclues ; traitement/total sur runs COMPLETED seulement, cohortes récentes immatures. Limite 100000 audits affichée si atteinte. Les compteurs publics utilisent des jours UTC, les cohortes une fenêtre glissante : dénominateurs distincts.

Activation et rétention de compte : voir le [plan du parcours compte](account-journey-measurement.md) pour les déclencheurs, dénominateurs, J+7/J+30 et limites. Les inscriptions non observées ne sont pas reconstituées ; les audits historiques gardent une audience inconnue. Aucun taux visite → compte/rapport, personne unique, gain causal ou objectif inventé. Premium reste réservé sans collecte. Le contrat admin est étendu de façon additive pour conserver les métriques d’audit pendant une mise à jour des applications.

Purge horaire de toutes les tables de mesure : faits/attributions au-delà de 90 jours, compteurs au-delà de 90 jours UTC. Cette purge ne touche aucun compte, audit, run ou rapport. Le retrait arrête les nouvelles observations ; les faits déjà consentis et agrégats suivent leur échéance. Les états des runs déjà consentis restent actualisés. Une panne de collecte ne bloque aucune fonctionnalité, sans reprise ni SDK tiers.

Les endpoints de compte vérifient session/propriété ; seuls les événements autorisés après accord reçoivent un credential BFF construit côté serveur. Les collecteurs publics gardent le schéma fermé, l’origine et le corps ≤2048 octets. Validation et limites réelles : [recette de livraison](../qa/account-journey-484-486.md). Aucune baseline historique ni donnée Search Console supposée disponible ; aucun gain annoncé.
