## Périmètre

Suite de la PR #611 (#599–#601), révision de départ `85b9eee9`. La PR précédente a été intégrée pendant ce travail ; `main` à `98580870` a ensuite été incorporé sans conflit à la branche, qui cible directement `main` dans la PR #616. Les changements concernent connexion, inscription, demande de réinitialisation, réinitialisation et vérification email. Aucun contrat API, schéma de données, règle de mot de passe ou mécanisme d’authentification ne change.

- `PasswordInput` conserve un seul champ natif, masqué au montage, avec un bouton Afficher/Masquer de type `button`, nommé en FR/EN et exposant son état. Le clic conserve le focus du champ quand il l’avait ; au clavier, le focus reste sur le bouton. La sélection est restaurée après changement du type. Autocomplete et collage restent natifs.
- Le lien de récupération se trouve dans le bloc mot de passe, avant le bouton de connexion et les alternatives sociales.
- La récupération explique l’action et nomme explicitement l’envoi du lien. Après acceptation, un message conditionnel non révélateur reçoit le focus ; le formulaire laisse place à une action pour corriger l’adresse, qui restitue sa valeur et son focus. Les erreurs permettent de réessayer. Les contrôles sont désactivés pendant la requête.
- Le texte distingue un mot de passe Argos d’un accès uniquement par fournisseur externe. Il ne promet pas d’email pour un compte sans identité `password`, conformément à `AccountAuthService.send(…, "RESET")`, et ne liste pas de fournisseurs potentiellement désactivés.
- `AuthShell` conserve la marque/retour au site, langue et thème, avec un footer aide/contact/confidentialité/conditions. Les boutons principaux utilisent les tokens de marque. Les règles de présentation sont isolées dans des modules SCSS dédiés ; `SiteNav`, `SiteFooter`, les tokens globaux et les styles des autres consommateurs de `AccountView.module.scss` restent inchangés.

## Vérifications automatisées

Depuis `apps/console-web` :

```powershell
npx vitest run src/components/account/AccountView.dom.test.tsx src/components/account/AuthExperience.dom.test.tsx --maxWorkers=1
npm test -- --maxWorkers=1
npx eslint src/components/account/AccountView.tsx src/components/account/AccountView.dom.test.tsx src/components/account/AuthShell.tsx src/components/account/PasswordInput.tsx src/components/account/AuthExperience.dom.test.tsx
npm run build
```

Les nouveaux tests exercent les trois champs de mot de passe en FR/EN (collage, sélection, pointeur, Tab/Espace/Entrée, absence de POST), l’ordre de la récupération, l’attente et les doubles envois, les confirmations conditionnelles, la correction d’adresse, les erreurs et les liens localisés des cinq écrans. Les tests existants conservent la couverture des liens absents/invalides, validations et sessions. Le bilan des exécutions est reporté dans la PR.
